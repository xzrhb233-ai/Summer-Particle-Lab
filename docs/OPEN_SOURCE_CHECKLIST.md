# 开源准备检查与发布门槛

本清单由当前仓库实际检查建立，日期 **2026-11-05**。范围是源码公开前的整理与核查；未创建远端仓库、提交、推送、打 tag 或发布软件。状态只对应本轮证据，不代表安全认证或工程模型确认。

## 自动化入口

| 命令 | 检查内容 | 不包含什么 |
| --- | --- | --- |
| `pnpm check:repo` | 当前 Git 索引及未忽略工作区候选；常见秘密模式、本机绝对路径、生成物、符号链接、5 MiB 单文件上限、必需文档 | 不扫描 Git 历史、不证明没有其他秘密；许可证未选时警告 |
| `pnpm check:release` | 上述检查 + 根项目 LICENSE 存在性门槛 | 不能自动判断权利归属或许可证兼容性；缺 LICENSE 明确失败 |
| `pnpm test` | 跨平台发现测试，运行核心 JS/WASM、协议及模拟路径；明确排除 49 个原生 CAD 案例 | 不是 GPU 硬件测试，不以缺少 Python 自动“通过”原生测试 |
| `pnpm test:cad` / `pnpm test:all` | 先检查原生环境，再运行选定测试；skip/TODO/取消/空运行视为失败 | 不证明任意几何、工程模型或所有平台均正确 |
| `pnpm validate:vv` | 独立 CPU 解析/参考比较、细化、参数试抽样，输出真实状态 | 梁细化可为 inconclusive；不是“整平台正确”的测试 |

报告保存到被忽略的 `artifacts/repository-check.json` 和 `artifacts/release-check.json`。报告含候选路径、大小、SHA-256 与检查位置，不含匹配到的密钥文本。生成物仍保留在本地；`.gitignore` 不会撤回已经跟踪或历史提交中的文件。

## 发布顺序

1. 完成 R17–R20 的维护者决定与权利核实，补根 LICENSE 和私密安全联系方式。
2. 在计划公开的精确提交上运行 `check:repo`、全部适用测试、V&V 以及历史秘密扫描；保存配置与结果。复核生成报告中的全部警告。

4. 人工审核将公开的源文件、文档、图片、模型与第三方 notices。分发 wheel/WASM/安装包时再审查对应二进制内含组件。
5. 最后才确定版本、tag、release 内容和发布动作。当前 `check:release` 的失败是诚实保留的门槛，不应通过放宽脚本来消除。
